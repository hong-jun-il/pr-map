# 0003. 평가는 `claude plugin eval` 대신 직접 만든 도구로 한다

- 상태: 채택
- 날짜: 2026-11-13
- 관련: `eval/run.ts`, `eval/score.ts`

## 배경

Claude Code에는 플러그인을 평가하는 `claude plugin eval` 명령이 있습니다. 스킬 있음·없음 비교, 반복 실행, LLM 채점, 보고서를 이미 갖추고 있어서, 직접 만든 도구 대신 쓸 수 있는지 시험했습니다.

## 결정

직접 만든 `eval/` 도구를 계속 씁니다. `plugin eval`에서는 방식 두 가지만 가져옵니다. 스킬 없이 돌린 결과와 비교하는 것, 그리고 LLM 채점을 3번 묻고 다수결로 정하는 것입니다.

## 근거

Claude Code 2.1.322, macOS에서 `profile-cache` 케이스를 스킬 있음·없음 1회씩 돌렸습니다.

- **git이 실행되지 않았습니다.** macOS의 `/usr/bin/git`은 Xcode 도구를 거쳐 실행되면서 시스템 임시 폴더에 캐시 파일을 씁니다. 평가용 격리 환경이 그 쓰기를 막습니다. PR Map은 수집과 검증에 git이 꼭 필요해서 분석을 시작하지 못했습니다.
- **스크립트로 채점할 수 없습니다.** 채점 종류는 `regex`, `tool_order`, `tool_used`, `file_exists`, `llm`, `baseline` 여섯 가지뿐입니다. 근거 줄이 정답과 겹치는지, `validate`를 통과하는지, 변경 줄 커버리지는 잴 수 없습니다.
- **판정 단위가 다릅니다.** 답변 전체를 기준 문장 하나와 비교해 통과·실패를 냅니다. 우리는 지도의 문장 하나하나를 그 근거 코드와 비교해야 합니다.

## 버린 대안

- **Homebrew git을 설치해 다시 시험:** 격리 환경에서 돌지는 확인하지 않았습니다. 돌더라도 줄 번호 채점은 여전히 따로 해야 합니다.
- **promptfoo, Inspect AI:** 시험하지 않았습니다. 같은 이유로 PR Map에만 있는 채점은 직접 짜야 합니다.

## 다시 볼 조건

- `plugin eval`에 스크립트 채점이 생길 때
- CI(Linux)에서 평가를 돌리게 될 때. macOS의 git 문제는 Linux에서는 생기지 않을 것으로 보입니다.
