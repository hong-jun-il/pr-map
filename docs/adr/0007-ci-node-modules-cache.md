# 0007. CI에서 `node_modules`를 통째로 캐시한다

- 상태: 채택
- 날짜: 2026-11-13
- 관련: PR #14, `.github/workflows/ci.yml`

## 배경

CI 작업 네 개가 각각 `npm ci`에 33~38초를 썼습니다. 실제 검사 시간은 넷을 합쳐 57초였습니다. `setup-node`의 `cache: npm`은 내려받은 패키지 파일만 캐시해서 설치는 매번 다시 했습니다.

## 결정

- `node_modules`를 `actions/cache`로 캐시합니다. 키는 운영체제, `node22`, `package-lock.json` 해시입니다. 캐시가 맞으면 `npm ci`를 건너뜁니다.
- 같은 PR에 새 커밋이 올라오면 앞선 실행을 멈춥니다. main 실행은 멈추지 않습니다.

## 근거

같은 커밋을 캐시 없이, 그리고 캐시가 채워진 뒤에 한 번씩 돌렸습니다.

| 작업                | 캐시 없음 | 캐시 있음 |
| ------------------- | --------- | --------- |
| 테스트              | 88초      | 37초      |
| 린트와 형식 검사    | 53초      | 30초      |
| 타입 검사           | 46초      | 9초       |
| 빌드 결과 검사      | 46초      | 11초      |
| 러너 사용 시간 합계 | 242초     | 96초      |

## 알아 둘 점

- 키의 `node22`는 글자일 뿐입니다. 워크플로의 Node 버전을 바꾸면 키도 같이 바꿔야 합니다.
- PR에서 만든 캐시는 그 PR만 씁니다. main에서 CI가 한 번 돌아야 다른 PR이 첫 실행부터 캐시를 씁니다.
- 설치 결과가 이상해 보이면 키 앞부분을 `deps-v2-`처럼 바꿔 캐시를 비웁니다.

## 버린 대안

- **가벼운 작업 세 개를 하나로 합치기:** 러너 사용 시간은 더 줄지만, PR 화면에서 무엇이 실패했는지 덜 보입니다.
- **테스트 구조 바꾸기:** 테스트마다 git 저장소를 만드는 부분을 줄이면 더 빨라지지만, 테스트끼리 상태가 섞일 위험이 있어 미뤘습니다.

## 다시 볼 조건

- 여러 Node 버전으로 CI를 돌리게 될 때
- 테스트 실행(약 30초)이 가장 긴 구간으로 불편해질 때
