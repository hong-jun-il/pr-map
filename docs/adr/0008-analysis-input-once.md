# 0008. 분석 입력은 한 번에 읽히고, 테스트는 선언과 줄 범위만 싣는다

- 상태: 채택
- 날짜: 2026-11-13
- 관련: `skill/pr-map/SKILL.md`, `src/cli/diff.ts`, `src/cli/collect.ts`, [측정 보고서](../../eval/reports/2026-11-13-token-reduction.md)

## 배경

분석 한 번에 입력 토큰이 9만~67만 개 들었습니다. 턴별 기록을 보니 모델이 입력 파일을 하나씩 읽고, 지도를 셸로 쓰려다 거부되어 두 번 쓰고, 테스트 diff가 입력의 절반을 넘는 PR이 있었습니다.

## 결정

- SKILL.md와 실행 지시는 `input.json`과 `diff.txt`를 한 번에 함께 읽게 합니다.
- 지도는 파일 쓰기 도구로 한 번에 쓰게 하고, 셸로 쓰지 않게 합니다.
- SKILL.md에 지도 형식 예시를 싣습니다. 스키마 파일은 형식 오류가 났을 때만 읽게 합니다.
- `input.json`은 들여쓰지 않고 항목마다 한 줄로 씁니다.
- `diff.txt`에서 테스트 파일은 본문 대신 테스트 선언과 그 안에서 추가된 줄 범위만 싣습니다.

## 근거

- PR 6개 합계로 입력 토큰 42%, 출력 토큰 39%, 시간 37%가 줄었습니다.
- 채점한 정밀도는 93.1%에서 93.5%로 그대로였고, 틀린 문장은 전후 모두 0개였습니다.
- 줄 겹침으로 본 필수 동작은 93개 중 90.5개에서 90개로 비슷했습니다.

## 버린 대안

- **테스트 diff를 그대로 두기**: #40의 `diff.txt`는 2,668줄이고 58%가 테스트였습니다. 한 번에 읽게 하자 모델은 뒤쪽 테스트를 본문 대신 이름 검색으로만 봤습니다.
- **스키마 파일을 계속 읽히기**: 6,600자를 실행마다 읽었습니다. 예시 약 2,000자로 대신해도 검증 통과율은 그대로였습니다.

## 다시 볼 조건

- 테스트 연결이 맞는지 채점하게 됐을 때. 연결 수가 110개에서 88개로 줄었는데, 빠진 연결이 필요했던 것인지는 확인하지 않았습니다.
- 지도 형식을 바꿀 때. SKILL.md의 예시와 스키마를 함께 고쳐야 합니다.
- TypeScript·JavaScript가 아닌 저장소에서 테스트 선언을 못 찾는다는 보고가 있을 때. 선언 찾기는 정규식 하나로 합니다.
