# 0004. 문장 채점은 다른 모델로 3번 묻고 다수결로 정한다

- 상태: 채택 (검증 전)
- 날짜: 2026-11-13
- 관련: PR #12, `eval/judge.ts`

## 배경

근거 줄이 정답과 겹치는지는 규칙으로 셀 수 있지만, 문장이 코드와 맞는 뜻인지는 사람이 읽어야 했습니다. 중·대형 PR은 문장이 수십 개라 사람이 다 읽을 수 없습니다.

## 결정

- 문장마다 "근거 코드가 이 문장을 뒷받침하는가"를 LLM이 판정합니다. 판정은 맞음, 일부 맞음, 틀림, 근거 불일치 중 하나입니다.
- 채점 모델은 분석 모델과 다르게 둡니다. 분석은 Sonnet, 채점은 Opus가 기본입니다.
- 같은 질문을 3번 따로 묻고 둘 이상 일치한 판정을 씁니다.
- 채점기에는 도구를 주지 않고, 저장해 둔 근거 코드만 보여 줍니다.

## 근거

- 답을 만드는 것보다 주어진 문장이 코드와 맞는지 확인하는 쪽이 좁고 쉬운 질문입니다.
- 같은 모델로 채점하면 같은 착각을 맞다고 볼 수 있습니다.
- 3번 다수결은 `claude plugin eval`의 `llm` 채점이 쓰는 방식입니다.
- 근거 코드는 LLM이 옮겨 적은 것이 아니라 git에서 읽은 것입니다. 줄 번호가 실제로 있는지는 `validate`가 따로 확인합니다.

## 아직 확인하지 못한 것

- **채점기가 사람 판정과 얼마나 일치하는지 재지 않았습니다.** 그래서 이 채점기로 낸 정밀도는 참고값입니다.
- 실제 PR 케이스(`pf-*`)의 정답지도 사람이 확인하지 않은 초안입니다.

## 다시 볼 조건

- 사람이 판정한 문장 50개쯤과 비교해 일치도(κ)를 냈을 때. 0.7보다 낮으면 채점 지시나 모델을 바꿉니다.
- 채점 비용이 부담될 때. 2026-11-13 실행에서 채점 12회에 추정 $9.68, 분석 13회에 $2.79가 들었습니다.
