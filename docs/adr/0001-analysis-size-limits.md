# 0001. 지도 대상 파일 50개, 파일당 diff 400행으로 제한한다

- 상태: 채택 (근거 일부 없음)
- 날짜: 2026-11-06 (파일 수), 2026-11-07 (행 수). 기록은 2026-11-13에 작성
- 관련: `src/cli/classify.ts`의 `DEFAULT_MAX_FILES`, `src/cli/diff.ts`의 `MAX_ROWS_PER_FILE`·`MAX_LINE_CHARS`, PR #3

## 배경

큰 PR을 그대로 분석하면 입력과 결과가 감당할 크기를 넘습니다.

## 결정

- 지도에 넣는 변경 파일은 기본 50개까지입니다. 넘으면 변경량이 작은 파일부터 미분류로 뺍니다. `.pr-map.yml`의 `maxFiles`로 바꿀 수 있습니다.
- `diff.txt`에는 파일마다 400행까지, 한 줄은 240자까지만 싣습니다. 넘는 부분은 생략했다고 적고, 에이전트가 필요하면 직접 읽게 합니다.

## 근거

- **50개: 근거 기록 없음.** 첫 커밋(`65ee213`)부터 있던 값이고, 커밋 메시지, 요구사항 문서, PR 어디에도 이유가 없습니다. 이 값으로 잰 적도 없습니다.
- **400행과 240자: 목적만 기록되어 있습니다.** 커밋 `4b1e3d1`에 "큰 파일 하나가 입력을 차지하지 않게 파일마다 제한한다"고 적혀 있습니다. 왜 400과 240인지는 기록이 없습니다.
- 2026-11-13 평가에서 가장 큰 케이스는 지도 대상 22개(변경 파일 44개)였습니다. 테스트와 문서가 미분류로 먼저 빠지기 때문에, 50개 근처는 아직 한 번도 돌려 보지 못했습니다.
