# 자동 실행 설치

`/pr-map setup`을 실행할 때 따르는 절차다. `<스크립트>`는 스킬 폴더의 `scripts/pr-map.js` 절대 경로이고, 명령은 설치할 저장소 안에서 실행한다.

**API 키 값을 다루지 않는다.** 키를 채팅에 붙여넣으라고 요청하지 않고, 값을 출력하거나 파일에 쓰지 않는다. 사용자가 채팅에 키를 붙여넣으면 사용하지 말고, 노출된 키이니 폐기하고 새로 발급하라고 안내한다.

1. **공급자 선택**
   사용자에게 공급자를 고르게 한다. 선택지는 Claude, Codex, Gemini이고, 설명을 덧붙이지 않는다. 이후 모든 `setup` 명령에 `--provider <claude|codex|gemini>`를 붙인다.

2. **상태 확인**
   `node <스크립트> setup --provider <공급자>`
   출력된 상태와 "다음 단계"를 사용자에게 보여준다. 이 명령은 저장소를 바꾸지 않는다.
   "설치 불가"가 나오면 이유를 전하고 중단한다.

3. **워크플로 설치** — 브랜치 푸시와 PR 생성을 사용자에게 알리고 승인을 받은 뒤 실행한다.
   `node <스크립트> setup --install --provider <공급자>`
   - 작업 중인 브랜치와 변경 내용은 건드리지 않는다. 기본 브랜치 기준으로 `pr-map/setup` 브랜치를 올리고 PR을 만든다.
   - `gh`를 쓸 수 없으면 PR 생성 링크를 출력하니 사용자에게 전달한다.
   - 기존 워크플로와 내용이 달라 실패하면 덮어쓸지 묻는다. 동의하면 `--force`를 붙여 다시 실행한다.

4. **시크릿 등록** — "다음 단계"에 나온 방법을 따른다.

   | 상태                             | 할 일                                                                                                                         |
   | -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
   | `gh` 사용 가능, 환경변수 키 있음 | 그 키를 저장소 시크릿으로 올려도 되는지 묻고, 동의하면 `node <스크립트> setup --secret-from-env --provider <공급자>` 실행                         |
   | `gh` 사용 가능, 환경변수 키 없음 | 사용자에게 출력된 `gh secret set` 명령을 **자기 터미널에서** 실행하라고 안내. 대화형 입력이라 에이전트가 대신 실행하지 않는다 |
   | `gh` 없음 또는 로그인 필요       | 출력된 웹 링크에서 등록하라고 안내. `gh`를 임의로 설치하지 않는다                                                             |

   API 키가 없는 사용자에게는 고른 공급자의 콘솔에서 발급하라고 안내한다. 등록이 권한 문제로 실패하면 저장소 관리자에게 요청하라고 안내한다.

5. **마무리**
   `node <스크립트> setup --provider <공급자>`를 다시 실행해 결과를 확인한다. 웹에서 등록해 시크릿이 "확인 불가"이면 사용자에게 완료 여부를 묻는다.
   끝나면 설치 PR 링크와, PR을 머지해야 자동 실행이 시작된다는 점을 알린다.
